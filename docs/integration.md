# Integrating into OLSA (future work)

This document is a design sketch for wiring `x-thread-poster` into the OLSA
pipeline. **It is not implemented in either repository.** The package is
standalone today; the OLSA repository has not been modified. The purpose here is
to make the later integration a small, reviewable change with the decisions
already written down.

Read [`design.md`](design.md) first, especially decision 12 (the operator
accepted the policy risk) and the verification matrix (the classic authenticated
DOM, a 2-tweet composer thread and a 2-tweet image thread are verified live; the
replies strategy, alt text, untested image variants, Premium note-tweets and the
new-client DOM are not). The official API remains the alternative that removes
the mechanism risk; this sketch assumes the operator's browser-path decision
stands.

## 1. Where OLSA is today

The relevant facts from the current pipeline:

- `src/olsa/domain/social.py` defines `SocialPlatform.X = "x"`, `SocialPost`,
  `Capabilities` and `PublishedPost`.
- `src/olsa/ports/social_publisher.py` defines the one-method-per-destination
  `SocialPublisher` protocol (plus `validate`).
- `src/olsa/pipeline/posts.py` keeps X as a **copy-only** target:
  `COPY_ONLY_TARGETS = (SocialPlatform.X,)` and
  `COPY_ONLY_CAPABILITIES = {SocialPlatform.X: Capabilities(max_body=280,
  max_title=0, max_media=1)}`. The run drafts an X post for manual publishing but
  `build_social_publishers()` in `src/olsa/adapters/__init__.py` constructs only
  Discord and LinkedIn publishers.
- `src/olsa/pipeline/steps/distribute.py` computes a per-target
  `idempotency_key(video_sha256, post, media_sha256)`, writes `PENDING` before
  the call and records `POSTED`, `FAILED` or `UNKNOWN` in `posts.json`.
- `prompts/weekly/x_thread_1.txt` writes the **first** post of the weekly X
  thread: the index of every paper, in Unicode Mathematical Sans-Serif Bold. The
  rest of the thread (per-paper replies) is not generated by the pipeline yet.

So integration has two halves: a publisher adapter (below) and the weekly thread
assembly that supplies the index plus the per-paper replies.

## 2. The port shape

From `src/olsa/ports/social_publisher.py`:

```python
@runtime_checkable
class SocialPublisher(Protocol):
    name: str
    destination: str
    capabilities: Capabilities

    def validate(self, post: SocialPost) -> None: ...

    async def publish(
        self,
        post: SocialPost,
        *,
        on_progress: ProgressCallback | None = None,
    ) -> PublishedPost: ...
```

`PublishedPost` carries `target`, `post_id`, `url` and `published_at`. Failures
must be translated into `olsa.domain.errors` at the adapter boundary; no
`xposter` exception type may cross the port. The relevant error classes are
`AdapterUnavailableError`, `PublishAuthError`, `PublishQuotaError`,
`PublishOutcomeUnknownError` and the `PublishError` base.

## 3. Sketch adapter: `XThreadPublisher`

Suggested location: `src/olsa/adapters/x_thread.py`. It imports `xposter`
**lazily inside the methods** so the pipeline still imports when the optional
extra is not installed.

```python
"""X destination for the OLSA social distributor (sketch, not implemented)."""

from __future__ import annotations

import hashlib
from dataclasses import dataclass
from pathlib import Path
from typing import Any

from olsa.domain.errors import (
    AdapterUnavailableError,
    PublishAuthError,
    PublishError,
    PublishOutcomeUnknownError,
    PublishQuotaError,
)
from olsa.domain.social import Capabilities, PublishedPost, SocialPost
from olsa.ports.progress import ProgressCallback

_X_LIMIT = 280


@dataclass(frozen=True, slots=True)
class XSettings:
    """The host-owned part of the X adapter configuration."""

    home: Path  # ~/.olsa/x
    handle: str = ""  # expected account, no @
    display: str = "auto"  # auto | headless | xvfb | visible
    strategy: str = "composer"  # composer | replies
    allow_alt_text: bool = False  # live alt editor still UNVERIFIED


class XThreadPublisher:
    """Publish one SocialPost as an X thread through x-thread-poster."""

    name = "x-thread"
    capabilities = Capabilities(max_body=_X_LIMIT, max_title=0, max_media=1)

    def __init__(self, settings: XSettings, *, poster: Any = None) -> None:
        self.destination = f"x:{settings.handle.lower()}"
        self._settings = settings
        self._poster = poster  # test seam; production builds it from xposter

    def validate(self, post: SocialPost) -> None:
        """Reject only what cannot be a thread before a browser starts.

        Do NOT reject a body longer than ``max_body``: an X thread is longer
        than one tweet by design. The splitter checks each resulting segment.
        """
        if not post.body.strip() and not post.title.strip():
            raise PublishError("X post has neither a body nor a pinned first post.")
        if len(post.media) > self.capabilities.max_media:
            raise PublishError(
                f"X accepts at most {self.capabilities.max_media} media file(s) per post."
            )
        for asset in post.media:
            if not asset.path.is_file():
                raise PublishError(f"X media file is missing: {asset.path}.")

    async def publish(
        self,
        post: SocialPost,
        *,
        on_progress: ProgressCallback | None = None,
    ) -> PublishedPost:
        del on_progress  # xposter has no step-progress hook; the job log is enough
        poster = self._poster_or_raise()
        text = self._body_text(post)
        first = post.title.strip()

        # Imported here, not at module import: xposter is an optional extra.
        from xposter import (
            PostOutcomeUnknownError,
            PostRejectedError,
            Thread,
            Tweet,
            UiChangedError,
            ValidationError,
            XPosterError,
            split_thread,
            split_with_first,
        )

        try:
            if first:
                segments = split_with_first(first, text, limit=_X_LIMIT)
            else:
                segments = split_thread(text, limit=_X_LIMIT)
            media = tuple(asset.path for asset in post.media)
            alt_texts = tuple(asset.alt_text for asset in post.media)
            tweets = [Tweet(segments[0], media=media, alt_texts=alt_texts)]
            tweets.extend(Tweet(segment) for segment in segments[1:])
            thread = Thread(tuple(tweets), key=self._post_hash(post))
            posted = await poster.post_thread(thread)
        except PostOutcomeUnknownError as exc:
            raise PublishOutcomeUnknownError(str(exc)) from exc
        except (PostRejectedError, ValidationError) as exc:
            raise PublishError(str(exc)) from exc
        except UiChangedError as exc:
            raise AdapterUnavailableError(
                f"X's UI no longer matches the bundled selectors: {exc}. "
                "Run `xposter doctor --dom` on the host."
            ) from exc
        except XPosterError as exc:
            raise _map_auth_or_quota(exc) from exc
        except OSError as exc:
            raise PublishError(str(exc)) from exc

        if not posted.tweets:
            raise PublishOutcomeUnknownError(
                "xposter returned no tweet ids; the post may or may not exist."
            )
        return PublishedPost(
            target=post.target,
            post_id=posted.tweets[0].id,
            url=posted.first_url,
            published_at=posted.posted_at,
        )

    def _body_text(self, post: SocialPost) -> str:
        """Put the link with the commentary, never as a bare link-only post."""
        text = post.body.strip()
        if post.link and post.link not in text:
            text = f"{text}\n\n{post.link}" if text else post.link
        return text

    def _post_hash(self, post: SocialPost) -> str:
        """Hash the visible inputs that identify the thread.

        This is deliberately content-only (target, body, title, link, media file
        names and alt texts), not OLSA's video-inclusive
        ``PostResult.idempotency_key``. Two layers protect different things: OLSA
        decides whether to call the adapter; xposter decides whether X already
        has this visible thread.
        """
        parts = [
            post.target.key,
            post.body,
            post.title,
            post.link,
            *(asset.path.name for asset in post.media),
            *(asset.alt_text for asset in post.media),
        ]
        return hashlib.sha256("\x1e".join(parts).encode("utf-8")).hexdigest()

    def _poster_or_raise(self) -> Any:
        if self._poster is not None:
            return self._poster
        try:
            from xposter import (
                Display,
                Strategy,
                XPoster,
                XPosterConfig,
            )
        except ImportError as exc:
            raise AdapterUnavailableError(
                "X posting requires the 'x-thread-poster' package; install the "
                "'x' extra on the host."
            ) from exc

        config = XPosterConfig(
            home=self._settings.home,
            handle=self._settings.handle or None,
            display=Display(self._settings.display),
            strategy=Strategy(self._settings.strategy),
        )
        self._poster = XPoster(config, allow_alt_text=self._settings.allow_alt_text)
        return self._poster


def _map_auth_or_quota(exc: Exception) -> PublishError:
    """Map the remaining xposter failures; keep this table next to the adapter."""
    from xposter import (
        AccountMismatchError,
        AccountRestrictedError,
        BrowserUnavailableError,
        ChallengeError,
        ConfigurationError,
        LedgerCorruptError,
        NotLoggedInError,
        PacingError,
        ParkedError,
        RateLimitedError,
        SessionBusyError,
    )

    if isinstance(
        exc,
        (
            NotLoggedInError,
            AccountMismatchError,
            ChallengeError,
            AccountRestrictedError,
            ParkedError,
        ),
    ):
        return PublishAuthError(str(exc))
    if isinstance(exc, (RateLimitedError, PacingError)):
        return PublishQuotaError(str(exc))
    if isinstance(
        exc,
        (
            BrowserUnavailableError,
            SessionBusyError,
            ConfigurationError,
            LedgerCorruptError,
        ),
    ):
        return AdapterUnavailableError(str(exc))
    return PublishError(str(exc))
```

The sketch is intentionally small. The real adapter needs the same error table
in one place, a fake `XPoster` for tests, and no network in `make check`.

## 4. Mapping `SocialPost` to xposter

### Body, title and the pinned index

- `post.body` is the thread text. It may be longer than 280 weighted
  characters; `split_thread` turns it into tweets. Do not use Python `len()`.
- `post.title` is reused as the **verbatim first post** for X. The weekly job
  puts the `x_thread_1.txt` index there; `split_with_first` keeps it exactly as
  written and never numbers or re-splits it, while the per-paper replies are
  split and numbered normally.
- If `post.title` is empty, the adapter splits `post.body` and the first
  segment is tweet 1 (normal `split_thread` behaviour). There is no pinned
  index in that case.
- The `SocialPublisher` port has no "thread parts" field. Reusing `title` is a
  small overload, but it avoids a port change. If the weekly job later needs a
  different first post per platform, extend the port explicitly (and record it
  in the ADR) rather than inventing a second hidden convention.
- `post.link`, when non-empty and not already in the body, is appended after a
  blank line. Keep the link with commentary: X's Authenticity policy prohibits
  link-only posting as the bulk of the account's activity, and the research memo
  recommends one link in one tweet per thread.
- `disclose_ai` has no X equivalent; ignore it in this adapter.

### Media

- `SocialPost.media` maps to `Tweet.media`; xposter supports per-tweet images,
  but the current OLSA `SocialPost` has one flat media tuple. Put those images on
  **tweet 1**: that is the post readers see in the card, and X's composer accepts
  up to four images per tweet. OLSA currently declares `max_media=1` for X and
  produces one wide image; keep that until the compose step generates more.
- Images attach through the modal's hidden `[data-testid="fileInput"]` with
  `set_input_files` and land in the **focused** editor; never click the media
  picker. This is `VERIFIED-LIVE` on a real 2-tweet thread with one image per
  tweet.
- Local validation is strict and happens before Chrome: PNG/JPEG/GIF/WebP only,
  extension and magic bytes must agree, at most **5 MiB per image** (15 MiB for a
  GIF), a GIF may not be mixed with another image, at most four per tweet, no
  duplicate paths, no zero-byte files, and **video is rejected**.
- **xposter never resizes.** The caller must fit images under 5 MiB. This matters
  for the OLSA pipeline: PDF page screenshots may exceed 5 MiB and must be
  downscaled/re-encoded before `publish`; do not rely on xposter to shrink them.
- `MediaAsset.alt_text` maps to `Tweet.alt_texts` one-to-one. Alt entry is
  **off by default** (`XPoster(allow_alt_text=True)` / CLI `--allow-alt`) because
  the live "Edit image description" field and Save are **UNVERIFIED**; without
  the flag a non-blank alt raises `ValidationError` before any browser starts.
  Leave alt off in the pipeline until the live flow is verified.
- A missing derived image or a validation failure is a normal `PublishError`
  without touching the account. The 2-image live thread and delete flow are
  `VERIFIED-LIVE`; >2 images, four per tweet, GIF/WebP/JPEG, near-limit/slow
  uploads and images with the replies strategy remain unverified.

### Length and thread limits

- `Capabilities.max_body` is documented as characters in the OLSA domain model,
  but X's limit is **weighted**: URLs count 23, code points outside twitter-text's
  light ranges count 2, one emoji sequence counts 2, and each Unicode
  Mathematical Sans-Serif Bold letter counts 2. Set `max_body=280` as the
  per-tweet limit, not as a limit on the whole `SocialPost`. The adapter's
  `validate` must therefore not reject a long body.
- X's composer caps one thread at 25 posts. `xposter` enforces the same limit
  and raises `ValidationError` before Chrome. The weekly edition (20–23 papers)
  must fit within 25 tweets including the index; if it cannot, split it into two
  threads or shorten the per-paper copy. This is a content decision, not an
  adapter workaround.
- The splitter protects URLs, hashtags, mentions and emoji sequences from being
  cut. It prefers paragraph, sentence and word boundaries, with a grapheme split
  only for an enormous token.

### Idempotency

Two keys exist and should not be conflated:

1. **OLSA's key.** `distribute.idempotency_key(video_sha256, post, media_sha)`
   includes the video hash and is stored in `posts.json`. It decides whether
   OLSA calls the adapter again.
2. **xposter's key.** `Thread.key` (the adapter's `_post_hash`) hashes the visible
   X content: target, body, title, link, media file names and alt texts.
   xposter's ledger uses `Thread.content_hash` (the key plus each tweet text and
   each media file name) to decide whether X already has the thread.

The second key is the last line of defence: even if OLSA retries because the
video changed, xposter returns the stored result instead of posting the same
visible thread twice. Renaming a media file changes both keys; keep derived
media names stable per variant.

For the weekly job, use a stable key such as `weekly-<ISO year>-W<week>` as part
of `Thread.key` (or make `_post_hash` include the target and body, which it
already does). Do not use a random key per attempt.

### What `PublishedPost` should contain

- `post_id` = the first tweet's id (`posted.tweets[0].id`).
- `url` = `posted.first_url`, which is the first tweet's permalink.
- `published_at` = `posted.posted_at` (ISO-8601 from the ledger).
- If `posted.tweets` is empty, raise `PublishOutcomeUnknownError` rather than
  recording an empty success.

## Pipeline features that feed xposter

Two accepted OLSA ADRs describe content that could feed xposter. **Neither is
integrated yet**, and the ADRs themselves say so; xposter does not call the
resolver or the region planner. This section records the mapping constraints for
the later adapter work.

### ADR-0084 — handle resolver

`docs/adr/0084-handle-resolver.md` (accepted 2026-11-10) adds a resolver that
returns a `HandleReport` with `username`, canonical URL, page kind, confidence
and evidence. It is **not wired into the pipeline, CLI or portal**; any browser
tagging/verification is explicitly later work.

- The plan is to tag paper authors and organisations on X/LinkedIn by typing
  `@name` through the logged-in browser. The resolver supplies the username; no
  platform ID or API lookup is needed.
- xposter already supports **typed mentions**: a known exact username typed with
  real key events is recognised by the Draft.js composer, with no dropdown
  selection. This is **VERIFIED-LIVE** for a real 2-tweet post on 2026-11-10
  (own handle only; line-final and tweet-final mentions rendered as real links).
  Mentions of **other** accounts, notification delivery and hashtag/cashtag
  typeahead remain UNVERIFIED.
- **The tension:** an automated account tagging authors or organisations is an
  **unsolicited automated mention** unless those users opted in. X's Automation
  Rules ("Automated mentions and replies", April 2026) say automating these
  actions "to reach many users on an unsolicited basis is an abuse of the
  feature, and is not permitted." xposter's default cap of **5 distinct non-self
  mentions per thread** will therefore refuse an every-author-every-tweet
  design. That is deliberate, not a bug.
- The operator must decide the posture. A suggested one: only resolver results at
  `high` confidence, a few per thread, for example in one tweet rather than every
  tweet; raise the cap only on purpose via `XPOSTER_MAX_MENTIONS_PER_THREAD` or
  `--max-mentions`. A wrong tag is public and permanent; a missing tag is
  invisible.

### ADR-0085 — paper regions

`docs/adr/0085-paper-region-selection.md` (accepted 2026-11-10) adds deterministic
figure/table extraction and text-only ranking. It produces a per-paper
`regions/` bundle and `regions.json`; **it adds no X client and posting is
separate work**.

- Tweet 1 is the existing `page-1.png` (copied to
  `regions/slot-01-highlight.png`). ADR-0085 only **warns** when that file is
  over 5 MB; xposter **refuses** images over 5 MiB (5,242,880 bytes) and never
  resizes. Integration needs an explicit resize/recompress step for page 1 before
  calling xposter.
- Tweets 2..N hold the crops selected per slot. `regions.max_images_per_slot`
  defaults to **2 and is never above 4**, which fits xposter's four-images-per-
  tweet limit.
- `regions.json` records **relative paths** and **caption-derived alt text**.
  Map each tweet's files to `Tweet(text, media=<paths>, alt_texts=<captions>)`;
  xposter attaches images per tweet and keeps the alt list aligned one-to-one.
- Alt text is **blocked behind `allow_alt_text=True` / `--allow-alt`** until the
  live "Edit image description" field and Save are verified. Integrating
  **without alt text at first** avoids that unverified path, but loses the
  accessibility text; that is a conscious decision to record, not an invisible
  default.
- Verify the crop files are PNG/JPEG (xposter accepts PNG/JPEG/GIF/WebP, but the
  ADR bundle renders PNG). GIFs are not expected here and must not be mixed with
  other images.

### Checklist additions for these features

- Add a **resize/recompress** step for any image (especially page 1) before it
  reaches `Tweet.media`; confirm the result is under 5 MiB, because xposter will
  refuse it and never resize.
- Make the **mention posture** an explicit ADR/operator decision: confidence
  threshold, how many per thread, which tweet(s), and whether the cap is raised.
  Do not let an every-author design fail at the default cap by accident.
- Keep **alt text off** until the live editor is verified; if it must be on,
  enable `allow_alt_text`/`--allow-alt` deliberately and accept that the flow is
  UNVERIFIED live.
- Verify the **image types** of the region bundle (PNG/JPEG expected) and that
  each tweet's files are under the per-tweet four-image limit.

## 5. Error mapping

The adapter must never leak an `xposter` exception type. Suggested table:

| `xposter` exception | OLSA exception | Why |
| --- | --- | --- |
| `NotLoggedInError`, `AccountMismatchError`, `ChallengeError`, `AccountRestrictedError`, `ParkedError` | `PublishAuthError` | The account/session needs a human; re-authenticate or unpark, then retry. |
| `RateLimitedError`, `PacingError` | `PublishQuotaError` | A budget or wait is exhausted; retrying now will fail again. |
| `PostOutcomeUnknownError` | `PublishOutcomeUnknownError` | A click may have landed; do not blind-retry. |
| `LedgerCorruptError` | `AdapterUnavailableError` | Local posting evidence is unreadable; restore or reset the ledger before retrying. This is not a platform outcome. |
| `PostRejectedError` | `PublishError` | The content was refused (duplicate/length); retrying the same content will not help. |
| `ValidationError` | `PublishError` | Invalid content or media before any browser work. |
| `UiChangedError` | `AdapterUnavailableError` | The adapter needs calibration (`xposter doctor --dom`) or a code update; metadata can fix it. |
| `BrowserUnavailableError`, `SessionBusyError`, `ConfigurationError` | `AdapterUnavailableError` | A backing dependency, lock or configuration is missing/fixable. |
| `XPosterError` (anything else), `OSError` | `PublishError` | Unknown failure; safe to report, not to classify as quota/auth. |

Preflight (before `publish`) can report a missing session as
`AdapterUnavailableError` with "run `xposter login` on the host". Once the
session is rejected by X, `PublishAuthError` is the right type.

Note the interaction with OLSA's own `PENDING`/`UNKNOWN` handling in
`DistributeStep`: an xposter `UNKNOWN` must become OLSA
`PublishOutcomeUnknownError`, which `DistributeStep` records as `UNKNOWN` and
does not retry without `--retry-unknown`. That is exactly the intended
two-layer quarantine.

## 6. Configuration, home and environment

### Where the session lives

The xposter home is **host state**, default `~/.olsa/x` and overridable with
`XPOSTER_HOME`. It already follows OLSA's `~/.olsa/<service>` convention (next to
`~/.olsa/youtube`, `~/.olsa/spotify`, `~/.olsa/social`).

Suggested `Settings` additions in `src/olsa/config.py`:

```python
x_dir: Path = Field(
    default_factory=lambda: Path.home() / ".olsa" / "x",
    description="Host directory with the X Chrome profile and posting ledger.",
)
x_handle: str = ""
x_display: str = "auto"  # auto | headless | xvfb | visible
x_strategy: str = "composer"  # composer | replies
x_enabled: bool = False
```

- The adapter builds `XPosterConfig(home=settings.x_dir, handle=settings.x_handle
  or None, display=..., strategy=...)` explicitly. It does **not** rely on
  ambient `XPOSTER_*` variables inside the pipeline, matching the project rule
  that entry points receive configuration explicitly.
- `XPOSTER_*` remains useful for the standalone CLI and for the keepalive timer:
  `XPOSTER_HOME=/home/olsa/.olsa/x`, `XPOSTER_HANDLE=...` in the systemd unit.
  Those variables are read by `XPosterConfig.from_env()`/the CLI, not by OLSA's
  pydantic `Settings` (whose prefix is `OLSA_`).
- Do **not** put the profile, `storage_state.json` or cookies in
  `~/.olsa/secrets.json`. The secret store holds named values; a browser profile
  is a directory of state. The portal cannot inject it, and rendering or logging
  it would be a credential leak. The session is created by `xposter login` on
  the host, exactly like the Spotify/YouTube login.
- The portal should show the cookie-free `SessionSummary` (handle, expiry,
  last verified, parked) and tell the operator to run `xposter login` on the
  host; a visible-browser login cannot run inside the web request. This mirrors
  the Spotify card (ADR-0082).

### Environment consistency

The login, keepalive and posting must run as the same OS user, on the same
machine and IP, with the same `home`. A login through a VPN and posts outside it
(or a copied profile) defeats the device/session consistency the design relies
on. Transferring only `storage_state.json` is the runbook's documented last
resort, not a normal move. The runbook's section 6 is the operational rule.

### Concurrency

The portal job runner serialises jobs per variant, but a systemd keepalive timer
is outside that lock. Both use the same xposter home, so two processes can
collide: xposter's `SessionBusyError` (exit 8) is the safe result. Either run the
keepalive when no post job is scheduled, or accept the occasional
`AdapterUnavailableError` and let the next run retry. Do not remove the lock.

## 7. Packaging: the optional `x` extra

The pipeline already depends on `playwright` (used for PDF/HTML screenshots), so
the new dependency is the package, not another browser. Suggested
`pyproject.toml` addition:

```toml
[project.optional-dependencies]
# X thread publishing through a saved Chrome session (`xposter login`).
# See docs/adr/0083-x-thread-publishing.md.
x = [
    "x-thread-poster>=0.1",
]
```

The package is not on a public index yet. At integration time either publish a
wheel to the private index or vendor one, then add the extra. If a path or git
URL is used temporarily, pin a tag/commit and record it in the ADR; do not leave
an unresolvable placeholder URL in `pyproject.toml`. `make dev-install` must
still succeed without the extra, and `make check` must pass with a fake
publisher, never a live X session.

## 8. The weekly thread prompt and Unicode-bold weighting

`prompts/weekly/x_thread_1.txt` writes only the **first** post of the weekly
thread: the index. It uses Unicode Mathematical Sans-Serif Bold
(U+1D5D4–U+1D61F) for headings and bullets. Those code points are above the
twitter-text "light" ranges, so each letter weighs **2** characters. Digits,
spaces, punctuation and emoji keep their normal weights, and every URL weighs
23.

`xposter.splitter.weighted_length` already implements those rules, and
`split_with_first` is the exact helper for the weekly shape:

```python
from xposter import split_with_first, validate_tweet, weighted_length

index = render_x_thread_index(edition)  # prompts/weekly/x_thread_1.txt output
replies = render_per_paper_replies(edition)

validate_tweet(index, limit=280)  # the index must fit unaided
segments = split_with_first(index, replies, limit=280)
# segments[0] == index verbatim (unnumbered)
# segments[1:] are the numbered per-paper replies
```

Important consequences:

- Do **not** measure the prompt output with `len()` or `textwrap`; a line that
  looks short can be over 280 weighted characters because of the bold alphabet.
  Use `weighted_length` before the browser starts, and fail the weekly job with
  a clear error if the index is over.
- Do **not** re-flow or number the index. The prompt explicitly forbids
  `1/`-style markers in it; `split_with_first` validates it and leaves it alone.
- The prompt says the later posts are "added elsewhere"; that is the
  `replies` part. If the weekly edition is generated as one blob, the job must
  split it into the index and the per-paper blocks before calling the adapter
  (or extend the adapter contract; see section 4).
- The prompt's `4–6 sections`, `2–8 papers per section` and "every paper once"
  rules are content checks, not length checks. A 20–23-paper index plus 20+
  replies can exceed X's 25-post thread cap; the job must plan the thread length
  (for example one reply per section, or two threads) and enforce 25 before
  posting.

## 9. The ADR to write in OLSA

The next free number after `0082-spotify-in-the-automatic-run.md` is **0083**.
Suggested record: `docs/adr/0083-x-thread-publishing.md`, following
`docs/adr/template.md`.

It should record, at minimum:

- **Status:** Proposed/Accepted, date, deciders.
- **Context:** X is copy-only today; the weekly thread needs a destination; the
  browser package exists and is verified offline; X's Automation Rules name
  scripting the website as a suspension trigger; the operator accepted the risk
  on 2026-11-09; the official API is the alternative.
- **Decision:** add an opt-in `XThreadPublisher` adapter behind the
  `SocialPublisher` port, installed through the `x` extra; keep X copy-only when
  the extra or the host session is missing; the session lives in `~/.olsa/x`;
  login/keepalive are host commands, not portal actions; xposter's ledger is the
  second idempotency layer; `UNKNOWN` maps to `PublishOutcomeUnknownError`.
- **Consequences:** policy risk remains; live DOM must be calibrated; a posted
  thread cannot be auto-retried; a browser lock can make a job fail as
  `AdapterUnavailableError`; the weekly job must respect 25 posts and weighted
  280; images must already be under 5 MiB because xposter never resizes; alt
  text is off by default and live-unverified; the package must be
  published/pinned; cleanup must not touch `~/.olsa/x`.
- **Alternatives:** official API only (recommended by the research memo, not
  chosen), API plus browser fallback, manual posting, direct GraphQL (rejected
  in the package design).
- Link back to the package design (`x-thread-poster/docs/design.md`) and the
  package README by repository name, not a relative path that would break
  inside the OLSA repo.

## 11. What not to do

- Do not import `xposter` from `olsa.domain` or at OLSA package import time; it
  is an optional extra, and the browser import must stay inside the adapter.
- Do not put `xposter` exceptions, `Path` objects from its ledger, or cookie
  values across the port. Translate at the boundary.
- Do not copy the profile or `storage_state.json` into CI, a container image, a
  project folder or another host. The session is created on the posting machine.
- Do not run the keepalive timer and a post job against the same home without
  accepting `SessionBusyError`; xposter's lock is what protects the profile.
- Do not treat a returned `PostedThread` as success without checking that it has
  tweet ids; an empty result is an unknown outcome.
- Do not claim multi-account support, proxy support or "undetectable"
  behaviour. None is implemented.
- Do not make X a default target in `social_targets` until the adapter, the
  session and the calibration are proven on the host; keep it opt-in.
